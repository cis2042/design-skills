# 从已有成果学习如何继续

本目录是技能自带的离线示例，不依赖操作者电脑上的 示例项目A/示例项目B 路径。示例引用原项目相对路径和摘录散列以便追溯；没有原仓库时仍可阅读和验证。原始成果快照日期为 2026-09-29，后续真实项目状态须重新核对。

## 必读路径

1. 先读[示例项目A 原成果摘录](example-a-source-excerpts.md)：真实模块规格、导航、Registry 和任务写法；来源散列在 [provenance](example-a-source-provenance.json)。
2. 再完整阅读[示例项目A 导入参与人员贯穿示例](example-a-functional-design-walkthrough.md)，按 00→06 学习怎样展开详细功能、逐页结构、逐操作流程和计划任务。这是主要范例；原规格、教学展开和待决项明确区分。
3. 用[示例项目A P02 页面拆分示例](example-a-pattern.md)对照另一业务链；接手已有成果时读[接续示例](continuation.md)。
4. 需要理解交付文件和机器索引组织时，再读[示例项目B 单功能包](example-b-install-plan/00-scope-and-sources.md)与 [delivery.json](example-b-install-plan/delivery.json)。它是格式与引用样例，不能代替 示例项目A 的详细功能整理过程。

## 样例各教什么

| 原成果 | 技能中的用法 | 不能照搬的内容 |
| --- | --- | --- |
| 示例项目A P06 功能规格、导航、Registry 及 P02-A11 任务写法 | 从模块详规到五个视图、七个动作、六类错误，再到可交接任务；主要贯穿案例 | 文件阈值、合并策略、恢复政策等尚未确认内容；教学建议不能变成已批准事实 |
| 示例项目A P02 及其动作/状态/结果 Registry | 从活动管理展开页签、预检、确认和结果；说明视觉父页依赖与任务粒度 | 活动管理业务、活动生命周期、冻结导航、抽屉宽度和人工审批策略 |
| 示例项目B F07/B06 与任务 2.2/2.6 | 把已完成的功能整理规范化为固定七份文档、机器索引和原任务定位 | Codex/Runtime 业务、双端要求、1280×1024、原项目全部完成状态 |

## 验证示例包

在技能根目录执行：

```bash
python3 scripts/validate_delivery.py examples/example-b-install-plan --require-ready
```

示例项目B 示例包是有限范围的格式教学规格：1 个功能、3 个 Surface、1 条旅程、2 项原任务映射。它没有覆盖整个 示例项目B，也没有替原项目勾选任务。脚本通过只证明结构检查通过，不证明符合 固定工作法新增的全部内容深度要求；教学审阅 pass 不可复制给新项目，真实新包必须重新审查来源、上下文、逐模块深度和产物一致性。

已有 示例项目B 全量功能计划只有两份主体文档，形成于本技能固定合同之前；它是素材来源，不是“天然满足八文件合同”的样板。这里显式演示如何补齐合同，避免把历史成果的遗漏复制下去。
