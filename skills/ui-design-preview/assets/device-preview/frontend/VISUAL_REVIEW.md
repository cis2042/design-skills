# 旧稿对照与交互复核

本轮以 `../review/pad-home.png`、`pad-discover.png`、`phone-settings.png` 以及冻结的 `alignment-baseline` 为视觉参照。保留 React、Ant Design、Ant Design Mobile 和共享状态，不回退到静态事件拼装。

| 页面/组件 | 对照差距 | 本轮调整 |
|---|---|---|
| 首页 | 图标重复、文字层级和状态不清楚 | 研究/代码/文档使用对应图标和克制配色；统一列表标题与辅助文字；任务状态使用语义色 |
| 能力目录 | 只有筛选和长列表，没有页面层次 | 恢复标题说明；Pad 两列卡片、Phone 单列；筛选与结果分区，保留分类选择与同步 |
| 搜索、任务、工作 | 页面缺少标题与用途说明 | 统一标题区、说明与内容间距，搜索结果保持紧凑 |
| 手机设置 | 没有旧稿的大标题，行与组间距偏松 | 标题改为“设置”；49px 设置行与 22px 组间距；底部可正常滚动访问 |
| 按钮与抽屉 | 曾出现对齐、hover、页脚截断 | 保留已验证的中等按钮、统一图文对齐/交互态、独立滚动与固定设置入口 |
| 下拉与弹窗 | iframe 下拉定位错误、弹窗滚动冲突 | 保留所属文档兼容层；复测真实展开与选择，保留固定操作区 |

## 验证方法

- `audit_matrix.py`：28 页面和 7 编辑器，29 尺寸/方向，浅深主题，检查溢出、弹窗边界、按钮高度。
- `audit_actions.py`：406 次编辑、同步、保存与启停。
- `audit_flows.py`：116 次模型、导入草稿、任务与消息流程。
- `verify_select_matrix.py`：58 次分类下拉展开、选择和同步。
- 额外回归：标准页面、布局稳定、Phone/Pad 功能对比、抽屉交互态、弹窗滚动。
- `capture_visual_review.py`：8 类关键页面 × 两端 × 两种主题，32 张实际浏览器截图，保存在 `evidence/visual-review/`。

自动检查不会判定“审美已通过”；关键截图需要人工查看。原型内模型获取、导入和任务仍为演示行为，测试不等于真实后端或真机验收。

## 本轮结果
最终静态构建：2,030 组布局检查 0 异常、无页面脚本错误；406 次配置操作、116 次流程、58 次分类选择通过。56 组页面回归、两端导航/表单对比、抽屉固定底部/交互态、按钮层级、输入稳定性及统一缩放检查通过。Switch 两端实际尺寸均为 36×22。旧稿对照页的四组图片链接已验证。

## 模型配置密度修正

模型页合并重复的标题、工作区标签和说明区，Pad 设置导航收窄到 180px，供应商导航保留 155px 避免名称换行。连接名称与协议在 Pad 并排显示；窄编辑区和 Phone 使用单列。字段间距 10px，模型行最小 46px，按钮和输入控件保持 40px。默认 Pad 配置卡从约 236px 提前到 156px，保存按钮从约 980px 提前到 774px。

本轮实际验证：`verify_model_density.py` 58 组尺寸/方向/主题，检查密度、控件高度、保存可达和编辑/保存同步；五个模型场景布局复核 290 组，0 溢出/弹窗边界/按钮高度问题，记录 `evidence/model-layout-audit.json`。模型改名状态、20 个 Pad 下拉、40 组页头和 7 组目录/编辑器对比通过。查看并更新四张模型页截图。业务服务仍是演示状态。

## 常规设置控件一致性修正

Phone 和 Pad 的语言/模式下拉均为 180×40px，选项值 14px。手机选择按钮显式设置内容布局和省略规则，避免库默认字号、图标撑高或铺满短选项。手机普通按钮文字也统一为 14px。提示条两端共用 Ant Design Alert，统一信息图标、背景、边框、字号与关闭按钮，并保留共享关闭状态。

`verify_control_parity.py` 已在浅深主题验证两端下拉宽高和字号、实际展开与选择同步、提示条高度/背景/边框/图标色一致与关闭同步。全页面布局矩阵本轮重新执行 2030 组，0 异常；20 个 Pad 下拉、设置焦点及布局稳定性、58 组模型密度回归通过。

## ZCode 输入区交互补齐

输入区使用独立 `src/composer.jsx`，保留 React/Ant Design 组件和双端共享状态。Pad 使用向上展开的选项菜单，Phone 使用底部面板；普通工具 32px，手机发送按钮 40px。输入支持多行，Pad Enter 发送、Shift+Enter 换行，并跳过输入法合成事件。

- 加号：本地附件、工作流、已启用插件、技能和智能体，可搜索并添加引用；支持 @、/、$ 入口。附件只保存文件名，未上传。
- 权限：计划模式、变更前确认、自动编辑、完全访问；当前仅记录会话选择，没有授予运行时权限。
- 模型：按已启用供应商分组，过滤已禁用模型；支持跳转管理模型。
- 思考强度：低、标准、高、最高，双端同步。
- 上下文：展示当前输入本地估算；容量、缓存命中率和额度未接服务，显示暂无数据。
- 引用条：可移除；发送后引用保留在用户消息中。

验证：`verify_composer.py` 验证上述选择、附件添加/移除、输入同步与发送，并检查 58 组尺寸/方向/主题；`verify_composer_panels.py` 检查 290 组选项面板边界（几何测试禁用过渡动画），记录 `evidence/composer-panel-audit.json`；`verify_composer_input_clearance.py` 检查 Pad 空输入和五行输入时菜单不遮挡输入文字。全页面矩阵重新执行 2030 组，0 异常；画布比例与输入保留回归通过。新增菜单截图及两端输入区截图可供评审。

## 输入草稿与等待列表

参考输入后的等待列表，将队列放在输入卡片顶部，当前草稿独立保留。演示回复进行中继续发送会加入队列，支持暂停/恢复自动发送、立即发送、行内编辑、删除、上移顺序与停止响应。队列与编辑状态在 Phone/Pad 共享；立即发送不清空当前草稿，停止或替换响应后旧计时器不会追加消息。队列项保存提交时的模型、权限、思考强度和引用快照。这里仅为本地演示状态机，不会发送模型请求，也不授予运行时权限。

短横屏中等待列表有独立滚动区域，附件缩略图收成文件引用，输入区保留可操作空间。`verify_chat_queue.py` 实际验证队列操作、双端同步、草稿保留、停止响应，并检查带等待项、图片与五行输入的 58 组尺寸/方向/主题组合；`verify_chat_queue.mjs` 验证 FIFO 自动发送、暂停、立即发送与旧响应防护。`verify_composer.py` 原有交互与 58 组布局回归通过。新增 `phone/pad-chat-queue-light/dark.png` 供评审。

## Pad 设置默认详情

Pad 的“设置”入口直接呈现常规设置，侧栏选中常规，右侧不再重复分类目录。Phone 保留分类目录；同步模式允许同一个设置入口呈现适合各设备的布局，具体分类和配置仍共享。Pad 页头返回工作区，Phone 详情返回分类目录。`verify_settings_landing.py` 覆盖 URL 直接进入、工作区入口、侧栏切换、返回动作、Phone 目录以及 Pad 横竖屏/浅深主题；`verify_control_parity.py` 保持选择和保存提示同步。
